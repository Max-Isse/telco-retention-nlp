# Data

## IBM Telco Customer Churn (real sample data, fictional customers)

- **Source:** IBM's GitHub, `IBM/telco-customer-churn-on-icp4d`, `data/Telco-Customer-Churn.csv`
  (URL and SHA-256 in `configs/config.yaml` and `data/raw_manifest.json`). 7,043 customers × 21 columns.
- **What it is:** a sample data set IBM publishes for analytics demos: a fictional telecom customer base with
  demographics, services, contract, billing, charges and a churn flag. One snapshot per customer; no dates.
- **Extended version (used):** IBM's extended sample (7,043 × 33: CLTV, Churn Score, Churn Reason, location),
  from Kaggle `yeanzc/telco-customer-churn-ibm-dataset`, saved as `raw/telco_extended.xlsx` and pinned by SHA-256. It
  matches IBM's basic file on all 7,043 ids and every shared field except `Dependents` (551 customers differ; D-002).
- **Cleaning:** 11 blank `TotalCharges` (all tenure 0) set to 0; no duplicate customers (D-005; lineage in
  `docs/data_lineage.md`).

## Customer Support on Twitter (phase 5)

Kaggle dataset `thoughtvector/customer-support-on-twitter` (real public tweets to and from brands' support accounts;
2,811,774 tweets), downloaded with the Kaggle CLI to `raw/twitter/` and cached as Parquet. Filter (D-018): opening
customer tweets whose first reply came from one of 8 US telecom support accounts, cleaned and de-duplicated: 83,138
tweets, almost all from October to early December 2017 (`processed/telecom_tweets.parquet`; volumes and steps in
`reports/themes.md`).

## Labels (phase 6)

- `labels/label_sample_ids.csv`: the 1,000 sampled tweet ids and their period (train = October 2017, test = later).
- `labels/llm_labels.csv`: theme, sentiment and urgency for all 1,000, labelled by an LLM (Claude) with
  `docs/labelling_guide.md`.
- `labels/human_labels.csv`: the same labels for 200 of them, labelled by hand (written by `telco import-labels` from the
  filled `human_to_label.csv`, which contains tweet text and is git-ignored).
- `labels/sentiment_failure_review.csv`: the category of each disagreement of the off-the-shelf sentiment model.

## Synthetic data

None so far. Any synthetic data (for example an illustrative ticket ↔ customer linkage) will be generated by a
script, carry SYNTHETIC in its file name and be listed here with the reason (D-001).

## Layout

- `raw/` — downloads as delivered (git-ignored); `raw_manifest.json` — committed provenance.
- `processed/customers.parquet` — the cleaned, contract-checked customer table (git-ignored, rebuilt by `telco data`).
